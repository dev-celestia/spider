# Port katana (Go) features 1:1 into browser-crawler (Rust)

Decisions confirmed with user: **full CLI binary** with katana's flag names, **native Rust approximations** for Go-ecosystem externals (jsluice, knowledge-base, capsolver, ja3/pprof), and **keep the existing Browser/PageIR/Builder API** working on top of the new engine.

## Target architecture

New modules under `src/` mirroring katana's `pkg/` layout; existing modules (`builder.rs`, `pipeline.rs`, `renderer.rs`, etc.) stay and get re-wired onto the new engine. New crate sections:

```
src/
├── lib.rs                  # existing + new module exports
├── types/
│   ├── mod.rs              # re-exports old types.rs + new options.rs, result.rs
│   ├── options.rs          # katana types.Options — every field from pkg/types/options.go
│   └── result.rs           # navigation::Request/Response + output::Result structs
├── engine/
│   ├── mod.rs              # katana engine.go: enum Standard|Headless|Hybrid dispatch
│   ├── common/             # base crawl loop (Shared, CrawlSession, per-host sessions),
│   │   ├── scope.rs        # scope Manager: dn/rdn/fqdn/custom-regex, in/out-of-scope (scope.go)
│   │   ├── filters.rs      # regex match/filter, extension match/filter, field filter (utils/filters)
│   │   └── ratelimit.rs    # global+per-host rate limit, delay, jitter (goflags jitrate equivalent)
│   ├── standard/           # plain reqwest crawl (standard/crawl.go)
│   ├── headless/           # headless_chrome-based crawl: browser pool, stealth (existing stealth.rs),
│   │                       # XHR extraction via CDP, automatic form fill, page-load strategies,
│   │                       # captcha hook (native capsolver HTTP client)
│   ├── hybrid/             # browser render + HTTP resource fetch crawl
│   └── parser/             # navigation extraction: all 3 header parsers (Link, Content-Location,
│                           #   Refresh) + all 26 body parsers (a[href], link, img, script, iframe,
│                           #   svg, meta, form, htmx, etc.) + custom-field regex parser
├── output/
│   ├── mod.rs              # StandardWriter: screen format (verbose [tag][method][depth]),
│   │                       # JSONL format with exclude-output-fields, output template
│   ├── fields.rs           # 14 field selectors (url,path,fqdn,rdn,rurl,qurl,qpath,file,ufile,
│   │                       #   key,value,kv,dir,udir) + store-fields per-host files
│   └── responses.rs        # store-response raw req/resp dump (-sr/-srd)
├── utils/
│   ├── queue.rs            # FIFO/LIFO/depth-first/breadth-first strategy queue
│   ├── knownfiles.rs       # robots.txt + sitemap.xml parsing (parser/files/)
│   ├── jsluice.rs          # native regex JS endpoint extractor (-jc/-jsl approximation)
│   ├── similarity.rs       # simhash + exact content dedup (-fsu path trie, -pcs simhash mode;
│                           #   tfidf/bm25 modes approximated with token-Jaccard)
│   ├── formfill.rs         # form field detection + fill data config (YAML)
│   └── extensions.rs       # default extension filter list
├── runner.rs               # katana internal/runner: validate options, parse inputs (args+stdin),
│                           # crawl orchestration, callbacks, error log, health-check, summary
└── bin/katana.rs           # clap CLI with katana's flag groups/shorts/defaults (from cmd/katana/main.go)
```

New dependencies: `clap` (CLI), `regex`, `governor` or hand-rolled token-bucket (rate limit), `publicsuffix` or `psl` (rdn/eTLD+1 for scope + fields), `serde_yaml` (form config), `trust-dns-resolver` optional. `scraper` already covers HTML parsing; `headless_chrome` already covers CDP.

## Feature checklist (1:1 from katana)

**Input/config**: multiple `-u` URLs + stdin, depth `-d 3`, crawl-duration, strategy depth-first/breadth-first, concurrency `-c 10`, parallelism `-p 10`, timeout, retries, delay, body-read-size, proxy, custom headers `-H`, resolvers (accepted; custom DNS via reqwest builder where feasible), ignore-query-params, max-domain-pages.

**Headless**: `-hl` full-browser crawl (existing dynamic renderer extended: per-page link extraction from live DOM, form fill, XHR capture via CDP Network events), `-hh` hybrid (browser fetch + static sub-resource fetching), system-chrome/scp, show-browser, headless-options `-ho`, no-sandbox, chrome-data-dir, no-incognito, chrome-ws-url (CDP connect), page-load-strategy (heuristic/load/domcontentloaded/networkidle/none) + dom-wait-time, time-stable, max-failure-count, auto-login `-al`, captcha solver provider/key (native capsolver HTTP client).

**Scope**: crawl-scope/crawl-out-scope regex lists, field-scope dn/rdn/fqdn/custom regex (via `psl` crate), no-scope, display-out-scope.

**Filters**: match-regex/filter-regex, extension-match/filter + no-default-ext-filter, dsl match/filter-condition (safe mini-evaluator over result fields: status_code, words, lines, body length, url), disable-unique-filter, filter-similar (+threshold, path-trie normalization), page-content-similar (simhash distance/tfidf/bm25 + budget), filter-page-type (error/captcha/parked heuristics).

**Parsing**: full header+body parser set above, js-crawl (`-jc` fetch JS files & extract endpoints, native), jsluice (`-jsl` native approximation), known-files `-kf all|robotstxt|sitemapxml` (auto depth-3), form-extraction `-fx` (form/input/textarea/select JSONL), xhr-extraction `-xhr`, extraction via custom field-config regexes, onclick JS link extraction (max-onclick-links), path-climb `-pc`.

**Output**: `-o` file, jsonl `-j`, no-color, silent/verbose/debug, fields `-f` + store-field `-sf` + store-field-dir, output-template `-ot`, store-response `-sr/-srd` + no-clobber, omit-raw/omit-body, list-output-fields, exclude-output-fields, error-log, tech-detect (native header/body tech fingerprints), output callbacks (OnResult/OnSkipURL as Rust closures).

**Runner/infra**: health-check self-diagnostics, resume (state file with queue+visited serialized to JSON), metrics summary, SIGINT graceful stop (tokio ctrl-c), TLS-impersonate flag (accepted, reqwest-level best effort), disable-redirects.

## Implementation order

1. **Types + utils**: `types/options.rs`, `types/result.rs`, `utils/queue.rs`, `utils/scope.rs`, `utils/filters.rs`, `utils/extensions.rs` + unit tests.
2. **Engine core**: `engine/common/` crawl loop (queue, per-host sessions, visited set, depth, concurrency via `Semaphore`, rate limiting, failure counts), `engine/parser/` navigation extraction, `engine/standard/`.
3. **Output**: `output/` writer (screen/jsonl/template), fields, store-response/store-field files.
4. **Runner + CLI**: `runner.rs`, `bin/katana.rs` with all flags grouped like katana.
5. **Headless/hybrid**: extend existing renderer into browser-pool crawler, XHR capture, form fill/extraction, auto-login, page-load strategies, captcha client.
6. **Advanced filters**: simhash/trie similarity, js-crawl/jsluice, known-files, path-climb, resume, health-check.
7. **Re-wire existing API**: keep `Browser::builder()` etc. compiling on top of the new engine; update examples + README.

## Verification

- `cargo build` + `cargo test` (unit tests per module mirroring katana's `*_test.go` where portable: scope validation, queue strategy, field formatting, path-trie, simhash, parser extraction).
- `cargo run --bin katana -- -u https://example.com -d 2` smoke test against a local test server (port katana's `internal/testutils` testserver into `tests/`), verifying screen + jsonl output, scope/filters, robots.txt known-files.
- Existing examples (`examples/example.rs`, `examples/single_page.rs`) still compile and run.
