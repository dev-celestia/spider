# Add Markdown output mode (Quick-Actions-style config expansion)

## Context

Goal: mirror Cloudflare Browser Rendering "Quick Actions" via config + CLI flags. Assessment of the core four:

- `/crawl` — already the crate's core capability.
- `/links` — already the default output (discovered URLs).
- `/content` — already available (response body via `--jsonl`, raw storage via `--store-response`).
- `/markdown` — **the only missing piece**: `transform_html_to_ir` (`src/transformer.rs:54`) converts HTML to Markdown, but it is not exposed as a crawl output mode.

So the work is a single vertical slice: a `markdown` output format through `Options` → CLI → `StandardWriter`, following the same pattern as the existing `json` flag.

## Changes

### 1. `src/types/options.rs` — new option field
- Add `pub markdown: bool` to the output section of `Options` (near `json` at line ~332), doc comment: "Output page content as Markdown instead of URLs/HTML (`-md`)."
- Update the manual `Clone` impl (~line 460) and `with_defaults()` (~line 485) — both must include the new field. No `validate()` change needed.

### 2. `src/bin/celestia-browser.rs` — CLI flag
- Add `markdown: bool` to the `Cli` struct output section (near `jsonl` at line ~322): `#[arg(long = "markdown")]` (long-only to avoid short-flag collisions; doc comment mirrors the Options field).
- Map it in `main()` output-options block (~line 496–506): `options.markdown = cli.markdown;`

### 3. `src/output/mod.rs` — `StandardWriter` markdown format
- Store `markdown: options.markdown` in `StandardWriter::new`.
- In `write()`:
  - Render the markdown **before** the `omit_body` clearing step (~line 269), since it needs `resp.body`.
  - Extend the format-precedence chain (line 277) from `template > JSON > fields > screen` to `template > JSON > markdown > fields > screen`.
- New `format_markdown(result)` helper: calls `crate::transformer::transform_html_to_ir(&request_url, &resp.body)` and emits `# {title}\n\n{markdown_ir}` (falls back to empty string when there is no response body, so the existing "result is empty" filter still applies).
- No interaction with JSON mode: `--jsonl` keeps its current shape; `--markdown` only changes the non-JSON formatting path. File output (`-o`) works automatically since it writes the same formatted string.

### 4. Tests
- Unit test in `src/output/mod.rs` (alongside existing tests, e.g. the json-mode test at ~line 692): construct an `Options` with `markdown = true`, feed a `Result` with a small HTML body, assert the output contains the markdown-rendered heading/paragraph and not the raw HTML.
- If `tests/e2e_cli.rs` has a harness pattern for flag checks, add a `--markdown` case; otherwise unit coverage is sufficient.

### 5. Docs
- Update the CLI flag list in `README.md` (or the relevant docs page under `playground/src/docs/pages/` if flags are documented there) with `--markdown`.
