# DFS Link-Tree: wire `SiteMapper` into the CLI

## Context
The tree model (`SitemapNode { url, depth, children }`) and the DFS recursive scan already exist: `SiteMapper::crawl_recursive` (`src/mapper.rs:89`) fetches each page, extracts same-host links, and recurses depth-first, producing the tree directly. Nothing algorithmic needs to change. The work is exposing it and hardening it.

## Changes

### 1. `src/mapper.rs` — harden + deduplicate the DFS crawler
- Add a `max_pages` option to `SiteMapperBuilder` (default `0` = unlimited) as a safety cap: DFS on a large site can otherwise run unbounded. `SiteMapper` tracks how many pages it has fetched and stops expanding once the cap is hit.
- Replace the inline `scraper::Selector` link scan in `crawl_recursive` with a call to `crate::transformer::extract_links(base_url, html)` (src/transformer.rs:203) — it already does same-host filtering, http/https validation, fragment stripping, and dedup, so the mapper keeps one source of truth for link rules.
- The recursion itself stays as-is (this is the DFS the user wants). Add a doc comment noting DFS semantics and the existing `-s breadth-first` flat strategy in the engine as the alternative.

### 2. `src/bin/celestia-browser.rs` — new `--sitemap-tree` flag
- Add `--sitemap-tree` bool flag. When set, skip the full crawl engine and instead run `SiteMapper` DFS over each `-u` URL.
- Flag mapping: `-d/--depth` → `max_depth` (i32 → usize, clamp ≥ 0), `--headless` → `RenderOptions { render_mode: Dynamic, .. }`, `-o/--output` → write pretty-printed JSON tree to the file; otherwise print to stdout.
- Multiple input URLs → JSON array of root nodes; a single URL → single root object.

### 3. Tests — `tests/` using the existing local-server helpers
Follow the `TcpListener`-based test server in `tests/common/mod.rs`:
- Tree shape: root children at depth 1, grandchildren at depth 2, depths increment correctly.
- Cross-page dedup: a link reachable from two parents appears only once in the tree (first DFS path wins).
- `max_depth` cutoff and `max_pages` cap behave as expected.

### 4. Docs
- `docs/API.md`: library example for `SiteMapper::builder().max_depth(n).max_pages(m).build()` + `map_site()`.
- `docs/USAGE.md` (or FEATURES.md): document the `--sitemap-tree` CLI flag with sample JSON output.

## Out of scope
- No BFS implementation (user chose DFS; the engine already offers `-s breadth-first` for flat scans).
- No playground/WASM changes.
